# PRP: mark-typst — Markdown to PDF via pandoc + typst (bashew)

> Confidence for one-pass implementation: **9/10** (pipeline verified locally on this machine, see "Verified Facts")

## Goal

Implement the `init` and `build` verbs in the existing bashew scaffold `mark-typst.sh` so that:

- `./mark-typst.sh init` — checks that `pandoc` and `typst` are installed, offers to install them if missing (via `brew install` on macOS / detected package manager elsewhere), and creates default config files: a `.env` with settings and a pandoc-typst template `mark-typst.template.typ`.
- `./mark-typst.sh build doc.md` — converts `../../examples/doc.md` to `../../examples/doc.pdf` **in the same folder as the input**, using pandoc (Markdown → Typst markup) and typst (Typst → PDF).
- `./mark-typst.sh build doc.md output/doc.pdf` — same, with explicit output path.
- Styling settings (font family, font size, paper size, margin, logo image, logo width) live in `.env` and are injected into the PDF via pandoc template variables.

## Why

- One-command "beautiful PDF from Markdown" for the user's documents, with company styling (logo, fonts) configured once in `.env`.
- Typst compiles in milliseconds (vs LaTeX) and pandoc handles full Markdown; combining them gives quality + speed.
- Bashew provides arg parsing, .env loading, logging, tempfile cleanup for free — the implementation is only the two `do_*` functions plus config lines.

## What

### Success Criteria

- [ ] `./mark-typst.sh init` creates `.env` and `mark-typst.template.typ` in the current directory (does not overwrite existing files unless `--FORCE`)
- [ ] `./mark-typst.sh init` detects missing pandoc/typst and offers installation (`IO:confirm`); with `-f/--FORCE` it installs without asking
- [ ] `./mark-typst.sh build doc.md` produces `../../examples/doc.pdf` next to `../../examples/doc.md`

- [ ] Markdown with headings, bold, code blocks, lists, tables, `---` rules and relative images converts without errors
- [ ] `shellcheck mark-typst.sh` passes, `./mark-typst.sh check` works

### Known Gotchas — bashew framework

```bash
# 1. VERBS: add to the choice line in Option:config() AND a case block in Script:main().
#    New choice line: choice|1|action|action to perform|init,build,check,env,update
#    (remove action1/action2/action3 placeholders everywhere)

# 2. TWO OPTIONAL PARAMS: replace `param|?|input|input file/text` with:
#      param|?|input|input markdown file
#      param|?|output|output PDF file (default: <input>.pdf)
#    Bashew assigns optional params positionally; both may be empty (e.g. for init).
#    do_build must die with a clear message when $input is empty.

# 3. .ENV AUTOLOAD: bashew sources (in order) <script_folder>/.env,
#    .<prefix>.env, <prefix>.env, then the same trio in cwd. So `.env` created by
#    init in cwd is loaded automatically on the next run — no manual sourcing.
#    Os:clean_env quotes values; lines are sourced as plain shell vars.

# 4. STRICT MODE: `set -uo pipefail` is active (nounset!). Any .env-provided var
#    MUST be referenced as "${FONT_FAMILY:-}" or given a default before use.
#    Pattern: font_family="${FONT_FAMILY:-Helvetica}" at the top of do_build.

# 5. IFS=$'\n\t' — word splitting on spaces does NOT happen. Build command
#    arguments as bash arrays: pandoc_args+=(-V "mainfont=$font_family").

# 6. Os:require "pandoc": with --FORCE it AUTO-INSTALLS via $install_package,
#    without it, it DIES with instructions. The spec wants "optionally install"
#    (= ask), so init needs its own confirm-then-install helper (see blueprint);
#    keep Os:require in do_build for the hard requirement.

# 7. IO:confirm returns 0 (yes) automatically when --FORCE is set — perfect for
#    non-interactive init in CI/validation.

# 8. The EXIT trap prints a scary error for ANY nonzero exit; always exit via
#    IO:die (clean message) rather than letting commands fail silently.
#    Check command success explicitly: pandoc ... || IO:die "pandoc failed".

# 9. Os:tempfile registers files in temp_files[] for auto-cleanup at exit —
#    but it puts them in $TMP_DIR, which BREAKS relative image paths (see below).
#    Register manually instead: temp_files+=("$typ_file").

# 10. `${action,,}` lowercase requires bash 4+ (bashew already enforces this).
```

### Known Gotchas — pandoc + typst

```bash
# A. CUSTOM TEMPLATE MUST BE SELF-CONTAINED: pandoc's typst body output references
#    `horizontalrule` (for `---` in md) and `$highlighting-definitions$` (for
#    fenced code blocks). The generated mark-typst.template.typ MUST contain:
#      #let horizontalrule = line(start: (25%,0%), end: (75%,0%))
#      $if(highlighting-definitions)$
#      $highlighting-definitions$
#      $endif$
#    plus the terms/table show-rules if desired (copy from `pandoc -D typst` header).

# B. TEMPLATE SYNTAX COLLISION: pandoc templates use $var$; typst uses #func().
#    They don't clash, but the heredoc in the bash script MUST be quoted
#    (<<'TEMPLATE_TYP') so bash doesn't expand $if(...)$ etc.

# C. RELATIVE PATHS: typst resolves image paths relative to the .typ FILE's
#    location. Therefore write the intermediate .typ NEXT TO the input .md
#    (e.g. $folder/.$(basename).typ), so `![](img/foo.png)` in the md keeps working.
#    Register it in temp_files[] for cleanup; with --VERBOSE, IO:debug its path.

# D. TYPST ROOT: `typst compile --root /` allows absolute paths (needed for
#    LOGO=/abs/path/logo.png in .env). VERIFIED working. Without --root, typst
#    refuses paths outside the .typ file's directory tree.

# E. FONT SIZE NEEDS A UNIT: fontsize must be `11pt`, not `11`. Template guard:
#    $if(fontsize)$$fontsize$$else$11pt$endif$. Document "11pt" format in .env.

# F. MISSING FONT: typst falls back silently (warning to stderr) if FONT_FAMILY
#    isn't installed. Surface typst's stderr to the user (don't swallow it).
#    Optional: FONT_PATH in .env → add `--font-path "$FONT_PATH"` to typst call.

# G. LOGO CONDITIONAL: only pass `-V logo=...` when LOGO is non-empty; the
#    template wraps it in $if(logo)$...$endif$ so no logo → no empty block.

# H. pandoc needs `-s` (standalone) to apply the template; without -s you get a
#    body fragment and the template is ignored.

# I. Markdown yaml frontmatter `title:` is picked up automatically by pandoc and
#    available as $title$ in the template — support it (nice freebie).
```

## Implementation Blueprint

### File contents generated by init

**`.env`** (heredoc `ENV_DEFAULTS` in the script; created only if absent, `--FORCE` overwrites):

```bash
### mark-typst settings — loaded automatically by mark-typst.sh
FONT_FAMILY=Helvetica
FONT_SIZE=11pt
PAPER_SIZE=a4
MARGIN=2.5cm
# absolute path to a logo image (png/jpg/svg), shown top-right; empty = no logo
LOGO=
LOGO_WIDTH=3cm
# extra folder with .ttf/.otf fonts (optional)
FONT_PATH=
# pandoc→typst template (created by `mark-typst init`)
TEMPLATE=mark-typst.template.typ
```

**`mark-typst.template.typ`** (quoted heredoc `TEMPLATE_TYP`, pandoc-template syntax):

```
#let horizontalrule = line(start: (25%,0%), end: (75%,0%))
$if(highlighting-definitions)$
$highlighting-definitions$
$endif$
#set page(paper: "$if(papersize)$$papersize$$else$a4$endif$", margin: $if(margin)$$margin$$else$2.5cm$endif$)
#set text(font: ("$if(mainfont)$$mainfont$$else$Helvetica$endif$",), size: $if(fontsize)$$fontsize$$else$11pt$endif$)
#set par(justify: true)
#show heading: set text(weight: "bold")
#show raw.where(block: true): block.with(fill: luma(245), inset: 8pt, radius: 4pt, width: 100%)
$if(logo)$
#align(right)[#image("$logo$", width: $if(logo-width)$$logo-width$$else$3cm$endif$)]
$endif$
$if(title)$
#align(center)[#text(size: 1.6em, weight: "bold")[$title$]]
#v(1em)
$endif$
$body$
```

(This exact template structure compiled successfully in the smoke test.)

### Task list (in order)

```yaml
Task 1 — Option:config():
  MODIFY choice line to: choice|1|action|action to perform|init,build,check,env,update
  REPLACE `param|?|input|input file/text` with two optional params:
    param|?|input|input markdown file
    param|?|output|output PDF file (default = input with .pdf extension)
  UPDATE script_description if desired (already "generate beautiful PDF from Markdown sources")

Task 2 — Script:main() case block:
  REPLACE action1/action2/action3 blocks with:
    init)  do_init ;;    # with #TIP lines: «mark-typst init»
    build) do_build ;;   # with #TIP lines: «mark-typst build doc.md [out.pdf]»
  KEEP check|env and update blocks as-is.
  REMOVE the generic `Os:require "awk"` line or keep (awk is used by bashew internals — keep it).

Task 3 — do_init():
  # pseudocode
  Tool:install "pandoc" "pandoc"     # helper, see Task 5
  Tool:install "typst" "typst"
  create .env from heredoc          -> skip+IO:alert if exists (unless FORCE)
  create mark-typst.template.typ    -> skip+IO:alert if exists (unless FORCE)
  IO:success "mark-typst initialized — edit .env to customize fonts/logo"

Task 4 — do_build():
  # pseudocode — all vars local, all .env vars read with ${VAR:-default}
  [[ -z "$input" ]]      && IO:die "need input file: mark-typst build <doc.md>"
  [[ ! -f "$input" ]]    && IO:die "input file [$input] not found"
  Os:require "pandoc" ; Os:require "typst"
  template="${TEMPLATE:-mark-typst.template.typ}"
  [[ -f "$template" ]]   || IO:die "template [$template] not found — run «mark-typst init» first"
  # default output: same folder, same basename, .pdf
  [[ -z "$output" ]] && output="${input%.*}.pdf"
  mkdir -p "$(dirname "$output")"
  # intermediate .typ NEXT TO input (gotcha C), registered for cleanup
  typ_file="$(dirname "$input")/.$(basename "${input%.*}").typ"
  temp_files+=("$typ_file")
  # build pandoc args as ARRAY (gotcha 5: IFS has no space)
  pandoc_args=(-s -o "$typ_file" --template="$template"
               -V "mainfont=${FONT_FAMILY:-Helvetica}"
               -V "fontsize=${FONT_SIZE:-11pt}"
               -V "papersize=${PAPER_SIZE:-a4}"
               -V "margin=${MARGIN:-2.5cm}")
  [[ -n "${LOGO:-}" ]] && pandoc_args+=(-V "logo=$LOGO" -V "logo-width=${LOGO_WIDTH:-3cm}")
  IO:debug "pandoc $input ${pandoc_args[*]}"
  pandoc "$input" "${pandoc_args[@]}" || IO:die "pandoc conversion failed for [$input]"
  typst_args=(compile --root /)
  [[ -n "${FONT_PATH:-}" ]] && typst_args+=(--font-path "$FONT_PATH")
  typst "${typst_args[@]}" "$typ_file" "$output" || IO:die "typst compilation failed"
  IO:success "created: $output"

Task 5 — Tool:install() helper (confirm-then-install, spec: "optionally install"):
  # pseudocode
  Tool:install() {           # $1 = binary, $2 = package
    local binary="$1" package="${2:-$1}"
    command -v "$binary" &>/dev/null && IO:success "$binary found: $(command -v "$binary")" && return 0
    if IO:confirm "Install [$binary] via '$install_package $package'?"; then   # FORCE ⇒ auto-yes
      eval "$install_package $package" || IO:die "installation of [$binary] failed"
      IO:success "$binary installed"
    else
      IO:die "cannot continue without [$binary]"
    fi
  }
  # $install_package is set by bashew's Script:meta (brew install / apt install / ...)

Task 6 — heredoc emitters:
  Env:example() { cat <<'ENV_DEFAULTS' ... }        # quoted heredoc
  Template:default() { cat <<'TEMPLATE_TYP' ... }   # quoted heredoc (gotcha B!)
  do_init writes:  Env:example > .env  /  Template:default > mark-typst.template.typ

Task 7 — validation (below) + fix everything shellcheck flags.
```

## Anti-Patterns to Avoid

- ❌ Don't modify the bashew boilerplate below line 172 — only Option:config, Script:main, helpers
- ❌ Don't use unquoted heredocs for the typst template ($if(...)$ would be mangled by bash)
- ❌ Don't put the intermediate `.typ` in `$TMP_DIR` — relative image paths break (gotcha C)
- ❌ Don't build command strings and `eval` them — use bash arrays (IFS gotcha)
- ❌ Don't reference `.env` vars without `${VAR:-default}` — nounset is active
- ❌ Don't swallow pandoc/typst stderr — font-fallback warnings must reach the user
- ❌ Don't reinvent .env loading, arg parsing, or tempfile cleanup — bashew already does it
- ❌ Don't ship a template missing `horizontalrule`/`highlighting-definitions` (gotcha A)
